# Đa ngôn ngữ (Tiếng Việt / English)

- **Mục đích:** Giao diện và file báo cáo xuất theo ngôn ngữ giáo viên chọn (vi / en).
- **File:** `src/shared/i18n.ts`, `src/renderer/src/lib/i18n.ts`, `src/main/reports/translate.ts`,
  `src/main/reports/reports.ts`, `src/main/settings.ts` (`lang` là key theo giáo viên)
- **Changelog:** [../changelog/i18n.md](../changelog/i18n.md)

## Logic chính

- Kiểu gettext: **chuỗi tiếng Việt là khoá**, bản English tra trong từ điển `EN` (`src/shared/i18n.ts`). Thiếu bản dịch
  → hiển thị tiếng Việt.
- `translate(lang, s, vars)` thay `{key}` bằng giá trị trong `vars`.
- Renderer: `const t = useT()` (hook đọc `settings.lang` từ store) → `t('Chuỗi tiếng Việt')`.
- `localizeStored(lang, s)`: dịch chuỗi do app sinh ra và **đã lưu bằng tiếng Việt** trong DB (lý do chấm tự động,
  issue phân tích tĩnh, ghi chú quét bài…) — tra `EN` rồi tới `EN_PATTERNS` (regex cho chuỗi có tham số). Chuỗi không
  nhận ra (vd output compiler) giữ nguyên.
- Nội dung do AI viết (lý do chấm, nhận xét) sinh theo `lang` của **chủ assignment** lúc chấm; khi xuất báo cáo nếu
  sai ngôn ngữ thì dịch lại bằng AI (xem `reports.md`).

## Lưu ý / giới hạn

- Chữ mới trên UI: viết tiếng Việt trong `t('…')` **và** thêm bản English vào `EN`.
- Chuỗi mới do main sinh và lưu vào DB có tham số: thêm regex vào `EN_PATTERNS`.
- Lỗi do main ném (`throw new Error('…')`) hiện nguyên văn tiếng Việt, chưa dịch.

## Test

`npm run typecheck`. Thủ công: đổi ngôn ngữ sang English trong Settings → kiểm tra trang vừa sửa không còn chữ
tiếng Việt (trừ dữ liệu người dùng nhập).
